## 架构

- **Web 与呈现层：** Next.js 15.5.24 App Router、React 18、Tailwind；`src/app` 放页面和 Route Handlers，`src/components` 放共享 UI，`src/hooks` 保留 React Query 数据与变更逻辑。页面与 Route Handlers 使用 Next 15 异步 request API。
- **业务与存储：** Auth.js 管理本站会话；Prisma 连接 PostgreSQL；媒体对象走 S3 兼容存储。生产 API 根域名规划为 `https://zhixing.xidian.edu.cn`。
- **校园知识 AI：** Next.js 后端通过 `src/lib/ai/rag.ts` 调用独立 Python `knowledge_service`；知识正文在 SQLite，向量检索使用 Qdrant，Embedding/Reranker 使用 BGE 模型。模型供应商仅由服务端调用。
- **参考代码：** `../references/twitter-clone` 是只读 UI 参考仓库，不属于产品构建或部署依赖。

## 生产部署入口

新 Web 服务的应用入口建议按以下顺序准备：配置生产环境 → `npm ci` → `npm run prisma:deploy` → `npm run build` → `npm start`，由 HTTPS 反向代理转发至 Next.js 服务。`npm run dev` 固定使用本地端口 `3002`；生产 `next start` 默认使用 `3000`，以 `PORT` 配置实际监听端口。

生产环境至少需提供 `DATABASE_URL`、`AUTH_URL`、`AUTH_SECRET`、西电 IDS 回调配置、S3 凭据，以及完成联调后再配置的 AI/RAG 服务变量。当前 `.env.local` 是开发配置，不应复制到生产。`npm run prisma:seed` 会执行 `prisma migrate reset` 并重置数据库，禁止在生产执行。

仓库 README 中的 EC2/PM2 步骤不是已验收的新版发布方案；现有部署目录主要覆盖知识服务。正式上线前还需确定目标 Git 仓库与发布流程，并补齐 Web 服务守护、反向代理、密钥管理、备份和回滚操作。
