# 前后端重写逻辑梳理

本文为整个平台的新技术栈重写提取业务行为、权限规则、数据关系和接口语义，不限定技术选型，也不复刻现有页面布局。重点详细梳理校园系统接口及校园服务。外部请求地址和字段根据当前实现记录；它们是现状，不代表学校承诺稳定的公开 API。

## 1. 平台范围与角色

- **普通用户**：通过西电统一身份认证 IDS 登录；拥有个人资料、校园信息和平台互动能力。
- **管理员**：独立登录和授权，处理内容审核、用户管理、校园知识资料和平台配置；管理员会话与普通用户会话分离。
- **平台域**：信息流与帖子、互动与关系、私信与通知、学院/社团分区、校园服务及日程、校园系统认证、校园知识问答、管理后台。
- 当前实现有 Flutter Web/移动端和微信小程序。重写应统一业务规则与接口语义，不需要保留两套页面结构。

## 2. 前端业务流程

### 2.1 登录与个人资料

1. 前端向本站创建 IDS 登录会话并打开授权地址。
2. 浏览器跳转西电 IDS，用户在 IDS 完成验证；IDS 将一次性票据回调本站。
3. 本站校验票据并创建/读取用户身份，移动端轮询会话领取本站令牌，Web 端从回调状态同步令牌。认证结果只能领取一次。
4. 登录后加载用户资料、隐私偏好、通知偏好和账号状态；退出时结束本站会话并清除本地令牌。
5. 个人资料支持昵称、头像、背景图及展示信息编辑；隐私设置控制私信等能力，通知设置控制用户接收偏好。

### 2.2 信息流与帖子

- 首页按频道/分区及排序浏览帖子；支持刷新、分页、搜索、标签筛选、学院/社团内容入口和热榜。
- 帖子支持标题、纯文本或 Markdown 正文、图片、标签、分区、公开/仅自己可见、匿名身份、评论开关、私信开关及社团发布身份。
- 帖子详情展示正文、作者/发布身份、分区、标签和互动状态；提供点赞、收藏、评论/回复、举报、复制、分享等操作。
- 成功发布后立即进入正常信息流，不设置“必须人工审核后才可见”的前置流程。风险命中可阻止发布或标记处理，后台仍可后续审核处置。
- 匿名发布时，对普通用户隐藏真实作者和头像；管理员仍能追溯真实账号。匿名帖子不显示可进入真实作者主页的入口，也不能作为私信发起来源。
- 用户可浏览和管理自己的帖子、评论、收藏、举报记录；可按权限编辑/删除自己的帖子和评论。

### 2.3 用户关系、私信与通知

- 用户可查看公开个人主页、关注/粉丝/好友列表；支持关注、取消关注、全局屏蔽和解除屏蔽。
- 私信以直接创建或复用会话为主。帖子入口要求帖子非匿名、允许私信且接收方隐私设置允许；个人主页入口也受对方隐私设置约束。
- 会话列表显示对方、最后消息和未读数；会话内收发消息、查看已读状态、屏蔽/解除屏蔽、从本人列表移除会话，并在规则允许时撤回消息。
- 评论/回复、互动和举报处理等事件形成通知；支持通知列表、未读数、单条已读和全部已读。
- 用户可提交账号注销申请、等级申请、置顶申请、申诉和意见反馈；需要审批的申请在个人端可查询处理状态。

### 2.4 学院与社团分区

- 综合、学院、社团分区使用统一内容流，分区目录提供类型、稳定 ID、名称、规则、启用状态和排序。
- 学院页按学院分区读取帖子。用户资料里填写的学院仅用于展示，不能授予学院发帖权。
- 用户可提交社团建立申请；管理员批准后创建社团及其对应分区，并将申请人设为负责人。社团详情展示资料、成员数和对应内容。
- 只有社团负责人/管理成员可用社团身份在该社团分区发布内容；不能代其他社团发帖。

### 2.5 校园首页、服务、日程与地图

- 登录后并行加载校园服务目录和今日日程。服务按配置分组展示，快捷入口按动作跳转。
- 服务动作可打开学校外链、本站日历/地图，或展示说明；详情按服务类型决定是否加载日历及关联地图。
- 今日安排按开始时间排序；若有正在进行的课程/考试/实验，突出第一项，否则突出最近一项未开始日程。
- 日历按日期分组展示课程、考试和实验，可切换日期范围与来源。常规日历通常读 7 天，考试视图读 31 天。
- 校园地图入口当前主要打开学校 GIS；本站返回的地图和楼宇坐标为示例索引，不是真实地图/室内定位能力。

### 2.6 校园系统认证中心

- **校园网**：获取图形验证码，输入校园网查询密码和验证码，后端代登录并校验登录后页面；响应中包含流量/在线设备摘要。
- **宿舍水机**：获取图形验证码，输入手机号和图形码申请短信，再输入短信码完成认证。
- 客户端仅保存认证成功标记、脱敏标识和时间，不保存密码或外部访问令牌；该标记不保证第三方会话仍有效。
- 当前宿舍水机只实现手机号认证，未实现设备列表、扫码绑定、启停接水或订单查询。

### 2.7 校园 AI 与管理后台

- AI 支持校园知识问答、语义检索、选中文本分析及热榜摘要。校园类问题检索适用的校园知识资料；通用检索可结合符合当前可见规则的公开帖子。回答返回可核验来源；模型地址/密钥由服务端持有。
- 管理后台提供总览、内容/图片审核、举报与申诉处理、账号管理、社团申请处理、频道/标签/分区和系统配置，以及校园知识文档、索引和 AI 检索记录管理。
- 管理动作需记录操作者、目标、处理结果和时间，并区分批准、拒绝、删除、风险标记等处理类型。

## 3. 后端业务规则

### 3.1 身份与授权

- IDS 返回的学号是可信身份依据；资料页自行填写的学院不能授予校内分区权限。
- 校园系统代理请求必须有有效本站会话，且学号必须等于当前用户本人学号；禁止将本站代理用作他人账号校验入口。
- 学院发帖权由服务端可信的“学号 → 学院分区”映射授予。无映射用户不能发学院帖；有映射用户只能发到匹配的启用分区。
- 社团身份需要负责人/管理成员关系及对应分区同时匹配；普通账号不能提交社团身份伪造发布者。
- 管理员与普通用户会话、权限分开校验；管理审批须写入处理记录。

### 3.2 内容可见性与互动

- 帖子可见性、删除状态、审核状态共同决定信息流、详情、搜索、个人列表和引用场景中的可见范围。
- 匿名只影响普通用户侧展示，后台保留真实作者追溯；匿名发布上下文不能绕过私信规则。
- 全局屏蔽、会话屏蔽、对方私信隐私和帖子私信开关共同约束私信创建与发送。
- 发布阶段有内容风险检查和频率限制；普通帖子发布后直接展示，人工审核属于后续管理处置。
- 评论、回复、互动和处理结果按事件创建通知；未读状态按接收用户保存。
- 账号注销采用申请及管理员审批，不能由用户直接物理删除账号。

### 3.3 校园服务与日程

- 服务目录包含 ID/slug、名称、分组、类型、认证提示、启用状态、排序、说明、动作和地图关联。动作类型有 `external`、`calendar`、`map`、`notice`。
- `authReady` 只是依据本站学号是否存在计算的展示值，不等于已登录任一外部校园服务。
- 日程统一存储/返回课程、考试、实验三类记录，按用户归属过滤；公共记录（没有用户归属）按当前逻辑共享读取。
- 当前有日程读取、分组、时间排序和进行中/下一项标记逻辑；没有发现从学校教务/一站式系统拉取或刷新课表数据的同步流程。
- 当前没有独立的校园服务目录管理 API；目录数据由服务端配置/种子数据驱动。

### 3.4 校园知识问答

- 校园问答检索校园知识文档，可按校区/培养层次等适用条件筛选证据；回答应基于检索证据并返回引用。
- 引用至少包含来源类型、标题、来源 URL 或平台目标、目标 ID。
- 管理侧支持资料创建、修改、状态调整/归档、索引重建和问答追踪查询。
- 模型密钥只存在服务端；知识检索失败不能静默降级为无依据回答。

## 5. 学校侧及校园系统接口

### 5.1 一站式入口：当前只有外链，没有一站式登录/API 对接

- 目录里的一站式地址是 `https://ehall.xidian.edu.cn/new/index.html`，动作为打开外部网页。
- 仓库未发现本站向 eHall 发起登录、OAuth/CAS 回调、交换 eHall 令牌/会话 Cookie，或调用 eHall 课表、成绩等业务 API 的实现；也没有可据以还原这些协议的接口地址、请求字段和响应样例。
- 服务目录中的 `requiredAccess`、`dataFields`、`features` 是展示/规划元数据。例如“需要一站式课表接口”只表达接入前置条件，不表示接口已接通。
- `authReady` 只在当前本站用户已有 IDS 学号、且该服务目录项配置为 `authType="ids"` 时为真，是前端提示字段，不代表浏览器已登录 eHall，也不代表本站持有 eHall 的 SSO 会话。

因此，若“学校一站式登录”指 eHall 本身的登录/免登，现有代码没有足够协议可供照搬；下文的 IDS CAS 是本站账号登录流程，不能当作 eHall 登录协议。

### 5.2 西电 IDS：本站使用的 CAS 服务票据协议

这是当前唯一确认接入的学校统一身份认证流程。IDS 凭据只在学校登录页输入；本站收到的是一次性 CAS `ticket`，通过服务端校验后再签发本站自己的 Bearer token。

| 本站接口 | 请求/跳转 | 返回与用途 |
|---|---|---|
| `POST /api/auth/xidian/session` | JSON：`platform`（`web`/`mobile`，默认 `web`）、`nextPath`（本站相对路径） | `200 {"data":{"attemptId":"…","status":"pending","platform":"web","authorizeUrl":"…/api/auth/xidian/start?attempt=…"}}`；创建 10 分钟有效的登录尝试 |
| `GET /api/auth/xidian/start?attempt={attemptId}` | 浏览器打开本站返回的 `authorizeUrl` | `302` 到 IDS 登录页；设置 HttpOnly、SameSite=Lax 的尝试 Cookie（HTTPS 时加 Secure），并固定 `service` 为 `https://zhixing.xidian.edu.cn/api/auth/xidian/callback` |
| `GET /api/auth/xidian/callback?ticket={ticket}` | IDS 带票据返回；本站还要求请求携带上述尝试 Cookie | 服务端校验 ticket。Web 成功后 `302` 回 `nextPath` 并附 `xidianAuthAttempt={attemptId}`；移动端返回完成页，由客户端继续轮询 |
| `GET /api/auth/xidian/session/{attemptId}` | 无请求体；Web/Mobile 轮询本站尝试状态 | `data.status` 为 `pending`、`validating`、`authenticated` 或 `failed`；成功时首次领取含 `token`、`verified`、`email`、`studentId` 的结果，重复领取不再返回 token |
| `POST /api/auth/logout` | 使用本站会话 | 退出本站会话，不会调用 IDS/eHall 的登出接口 |

上游协议细节：

1. 登录跳转目标为 `https://ids.xidian.edu.cn/authserver/login?service=<本站固定回调地址>`。
2. 回调收到 `ticket` 后，本站服务端依次尝试 `https://ids.xidian.edu.cn/authserver/p3/serviceValidate` 和 `https://ids.xidian.edu.cn/authserver/serviceValidate`，均以 HTTP GET 传 `service`、`ticket`。票据明确无效时立即失败；网络或响应格式/服务可用性错误才继续尝试兼容地址。连接/读取超时分别为 10/30 秒。
3. 响应按 CAS XML 解析 `authenticationSuccess` / `authenticationFailure`。身份字段从 `user`、`studentId`、`uid`、`username` 中识别学号；邮箱从 `mail`、`email`、`campusEmail` 中识别。没有学生邮箱时按 `{studentId}@stu.xidian.edu.cn` 补出本站邮箱。
4. 成功后本站创建或更新用户、记录登录审计并生成自己的随机会话 token；ticket 不下发给前端。attempt 状态在内存中保存，认证结果只能消费一次。Web 回调拿到的 `xidianAuthAttempt` 仍需轮询接口领取本站 token。

CAS 验票请求示意（字段由 HTTP query 编码，不是 JSON）：

```text
GET https://ids.xidian.edu.cn/authserver/p3/serviceValidate
    ?service=https%3A%2F%2Fzhixing.xidian.edu.cn%2Fapi%2Fauth%2Fxidian%2Fcallback
    &ticket=ST-...
```

`session` 创建/轮询和退出接口成功响应为 UTF-8 JSON，普通成功体以 `data` 包裹，错误体为 `{"message":"…"}`；`start`、`callback` 成功时是 HTTP 重定向或 HTML 页面，不是 JSON。IDS 登录功能受服务端开关控制；部署配置还固定了回调 Origin，不能由客户端传入任意 callback URL。

### 5.3 校园网自服务：学校网页表单代理

本站接口需要登录态，统一使用 `Authorization: Bearer <本站token>`；请求/响应为 JSON，成功体以 `data` 包裹。

| 本站接口 | JSON 请求 | 成功响应 |
|---|---|---|
| `POST /api/campus/auth/schoolnet/captcha` | `{"identifier":"本人学号"}` | `data.attemptId`、`imageBase64`、`imageContentType`、`expiresInSeconds`（当前 480 秒） |
| `POST /api/campus/auth/schoolnet/login` | `{"attemptId":"…","identifier":"本人学号","password":"校园网查询密码","captcha":"图形码"}` | `data.system="schoolnet"`、`status="authenticated"`、`studentId`、`usage`、`message` |

`identifier` 必须对应本站当前用户的 IDS 学号，不能代理查询其他学号。上游是 `https://zfw.xidian.edu.cn`，不是 eHall：

1. 服务端新建一个有 Cookie 状态的 HTTP 会话，GET `/login`，从 HTML 隐藏输入项提取 CSRF 名/值和 RSA 公钥。
2. GET `/site/captcha?refresh=1&_={毫秒时间戳}` 刷新，再 GET `/site/captcha` 取图片；本站将会话、CSRF 和公钥临时绑定到随机 `attemptId`，有效 8 分钟。
3. 登录时用页面公钥按 RSA PKCS#1 v1.5 加密校园网查询密码并 Base64 编码。POST `/site/validate-user` 表单字段：`LoginForm[username]`、加密后的 `LoginForm[password]`、`LoginForm[verifyCode]`；请求头带 `X-CSRF-Token`、`X-Requested-With: XMLHttpRequest`。预校验响应按 JSON 的 `success`、`message` 判断。
4. 预校验通过后，在同一 Cookie 会话 POST `/`，表单含动态 CSRF 字段名、用户名、加密密码、空 `LoginForm[smsCode]` 和验证码；随后 GET `/home` 并检查登录状态。
5. 从 `/home` 表格提取 `usage.summary={used,rest,charged}` 和 `usage.onlineDevices=[{ip,location,used}]`。该响应只是登录后当次摘要，本站没有持续同步或持久化校园网会话。

这是依赖学校登录页 HTML、CSRF 和 RSA 公钥的网页表单流程，不是稳定公开的数据 API。后续重写前需要核实学校当前页面协议及接入授权；本站不保存密码，也不向客户端暴露上游 Cookie。

### 5.4 课表、日程、服务目录和地图：本站本地 API

以下 `/api/campus/*` 查询接口都受本站登录态保护，使用 `Authorization: Bearer <本站token>`；成功响应为 `{"data":...}`。它们读取本站数据库/配置，不会请求 eHall 或教务系统。

| 本站接口 | 参数 | 返回结构/语义 |
|---|---|---|
| `GET /api/campus/schedules/today` | 无 | `data={date,items}`；每条日程含 `id`、`ownerUserId`、`source`、`sourceLabel`、`title`、`date`、`startTime`、`endTime`、`timeRange`、`location`、`teacher`、`section`、`kind`、`seatNo`、`examType`，并附 `isActive`、`isEmphasized` |
| `GET /api/campus/schedules/calendar` | `startDate=YYYY-MM-DD`、`days`、`source` | `data={startDate,endDate,days:[{date,weekday,isToday,items}]}`；无效/缺省日期回退到当前周周一，默认 7 天，`days` 限制为 1–31 |
| `GET /api/campus/services` | 无 | 启用的服务目录，按 `sortOrder` 排序 |
| `GET /api/campus/services/{id或slug}` | 服务 ID 或 slug | 单个服务元数据，并附 `maps`（按 `mapIds` 关联） |
| `GET /api/campus/quick-links` | 无 | 仅返回 `groupId` 为 `quick`/`tools` 的启用目录项 |
| `GET /api/campus/maps` | 无 | 返回本站 `campusMaps` 配置/种子数据 |

日程 `source` 值：`courseSchedules`（课表）、`examSchedules`（考试）、`experimentSchedules`（实验）、`academic`（只合并课程和考试）以及 `all`/空值（不按来源过滤，包含三类）。日程按日期、开始/结束时间、ID 排序；今日接口使用 UTC+08:00 中国标准时间，先强调正在进行的第一项，否则强调下一项未开始日程。

日程记录位于本站 `courseSchedules`、`examSchedules`、`experimentSchedules` 集合；`ownerUserId` 为空的记录按当前实现作为共享记录，非空时只返回给对应本站用户。仓库没有发现这些集合的公开写入/导入 API，也没有从学校端拉取或刷新课表的任务。服务目录对象字段包括 `id`、`slug`、`name`、`groupId`、`groupName`、`kind`、`iconKey`、`authType`、`authReady`、`status`、`description`、`requiredAccess`、`features`、`dataFields`、`calendarSource`、`emptyText`、`mapIds`、`actions`、`path`、启用状态及排序信息；`actions.type` 主要是 `external`、`calendar`、`map`、`notice`。`authReady` 不是学校服务登录态。

地图数据中有内置地点索引和外部 GIS 地址 `https://gis.xidian.edu.cn/#/home?campus=21047`；坐标/楼宇结构来自本站种子配置，不是 GIS API 响应，也不具备真实室内导航能力。

### 5.5 宿舍水机：第三方手机号认证，不属于信息中心校务 API

本站接口也要求 Bearer token。图形验证码会话绑定本站用户，当前有效期 5 分钟；短信发送按手机号限流。

| 本站接口 | JSON 请求 | 成功响应重点 |
|---|---|---|
| `POST /api/campus/auth/dorm-water/captcha` | `{}` | `sessionId`、`imageBase64`、`imageContentType` |
| `POST /api/campus/auth/dorm-water/sms` | `sessionId`、`phone`、`imageCode` | `status="smsSent"`、脱敏前手机号、消息 |
| `POST /api/campus/auth/dorm-water/login` | `sessionId`、`phone`、`smsCode` | `status="authenticated"`、`phone`、`uid`、`eid`、`hasToken` |

上游 `https://i.ilife798.com` 协议：`GET /api/v1/captcha/?s={16位数字会话ID}&r={刷新值}` 取图；`POST /api/v1/acc/login/code` JSON `{s,authCode,un}` 申请短信；`POST /api/v1/acc/login` JSON `{cid:"",authCode,un}` 校验短信。成功条件是响应 JSON `code == 0`；最终登录还要求 `data.al.token` 存在。本站仅返回 `uid`/`eid` 和 `hasToken`，不把第三方 token 下发或持久化；当前不包含设备绑定/控制、订单等能力。

### 5.6 校园知识检索：本站内部服务协议（非学校 API）

校园问答通过本站 `/api/ai/*` 调用单独部署的知识检索服务。此服务会检索已维护的学校公开资料/人工整理文档；资料 URL 或知识内容不代表学校提供了可供系统调用的业务 API。

信息中心公开网页的知识采集是另一条普通网页抓取链路：维护的公开页面 URL 通过 HTTP GET 获取，发现页从 HTML 链接中筛选文档/服务页面，再由本站内部 `POST /ingest` 抽取和索引。仓库没有发现信息中心提供的、用于读取学生私有校务数据的结构化 JSON API。

- 内部协议为 HTTP JSON；除 `GET /health` 外，请求需带 `Authorization: Bearer <KNOWLEDGE_API_KEY>`。成功体由操作返回 JSON；错误体为 `{"error":"…"}`。默认监听 `127.0.0.1:8091`（可由部署配置改写），密钥由服务端持有；业务后端用 `BACKEND_RAG_API_KEY` 配置同一把访问密钥。
- 已实现路由：`GET /health`、`GET /status`、`GET /documents`、`GET /documents/{id}`、`GET /documents/{id}/content`、`GET /traces/{traceId}`；`POST /search`、`/documents`、`/documents/status`、`/ingest`、`/reindex`、`/traces`。
- `/search` 请求字段为 `query`、可选 `queries`、`limit`、`includeCommunity`、`filters`、`traceId`；`/ingest` 用 `{url}` 获取并索引网页；文档新增/修改由标题、正文/来源 URL、authority、发布时间和适用范围等字段构成。状态接口支持 `published`、`disabled`、`archived`。
- 对外暴露给客户端的是本站 `/api/ai/chat`、`/api/ai/search` 等路由，不是此内网地址或 API key。管理端 `/api/admin/ai/knowledge-sources`、`/api/admin/ai/reindex`、`/api/admin/ai/traces/{traceId}` 再由本站服务端转调知识服务。

## 6. 已实现与未接入边界

- 当前确实连接外部系统的逻辑：本站账号通过 IDS CAS 登录；校园网自服务网页表单认证和登录后页面解析；宿舍水机第三方手机号认证。只有前两项涉及学校官方系统，水机上游为第三方。
- 服务目录、快捷入口、日历展示、示例地图索引和校园知识问答已有本站逻辑。
- eHall 当前仅有外链；未发现 eHall 专用登录、免登会话交换或业务 API 协议。IDS CAS 流程只用于建立本站账号会话。
- 课表、考试、实验日程的数据结构和读取 API 已存在，但没有发现从学校教务/一站式系统更新日程的数据流程；目录项提到成绩/空闲教室/考勤/电费/借阅/校园卡/报修/请销假等需求，不代表这些学校数据 API 已接入。
- 校园地图/楼宇点位是内置示例，没有真实地图、室内导航或楼层结构数据源。
- 重写如需真正接入 eHall/教务数据，需取得学校授权及接口文档（登录协议、接口地址、字段、分页/更新策略、错误码和用户身份映射）；不能从目录文案、外链、IDS CAS ticket 或本地数据结构推导学校 API。

## 7. 重写所需的核心数据对象

- **User**：本站 ID、IDS 学号/邮箱、昵称、头像/背景图、账号状态、等级、隐私和通知偏好。
- **Section**：类型、稳定分区 ID、名称、规则、启用状态及排序；学院权限映射与资料字段分离。
- **Post**：作者、标题/正文/格式、图片、标签、分区、公开范围、匿名信息、评论/私信开关、社团发布身份、状态及时间。
- **Comment**：帖子、作者、回复目标、正文、匿名/审核/删除状态、点赞及时间。
- **SocialEdge / Block**：关注关系、全局屏蔽关系。
- **Conversation / Message**：参与者、最后消息/未读状态、双向屏蔽、消息内容/已读/撤回状态。
- **Notification**：接收人、事件类型、关联对象、摘要、已读状态及时间。
- **Application / Report / Appeal**：申请或举报类型、提交者、目标、状态、处理人/时间和处理说明。
- **Club**：名称、介绍、分区、负责人及成员关系。
- **CampusIdentity**：本站用户 ID、IDS 学号、校园邮箱及认证状态。
- **CampusService / CampusAction / CampusMap**：服务目录、分组、动作配置和地图索引。
- **CampusSchedule**：用户归属、来源、标题、日期、起止时间、地点、教师、节次、考试类型及座位号。
- **CampusAuthAttempt**：本站用户、外部系统、会话/验证码标识、过期时间和流程状态；不得保存明文密码。
- **KnowledgeDocument / Citation / AiTrace**：知识来源、正文、适用范围/状态、检索片段、引用和问答追踪。
