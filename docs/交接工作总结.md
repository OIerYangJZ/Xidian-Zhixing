## 三、当前已确认的问题与缺口

### P0：会阻断个人主页访问的运行时错误

以下服务端页面拼接了未配置的 `process.env.URL`：

- `src/app/(protected)/[username]/getProfile.tsx`
- `src/app/(protected)/[username]/(tabs)/photos/page.tsx`

因此会出现：`Failed to parse URL from undefined/api/users/local-test-student`。应改为服务端直接调用 Prisma/共享查询函数，或者使用明确配置的站点 Origin，不能在服务端依赖未配置的 `URL`。

### P0：管理员规则尚未按最新需求落地

- 当前导航只根据 `session.user.role === 'ADMIN'` 显示一个“内容审核”入口。
- 当前服务端管理员校验在 `src/lib/ai/admin.ts`，只检查用户 `role=ADMIN` 和账号状态。
- 没有“按学号配置管理员账号”的后台配置模型和完整 API。
- 没有把所有管理功能统一收进管理员 Tab；目前只实现了知识管理和内容审核的一部分页面/API。
- 本地测试账号在 `src/auth.ts` 中被固定设为 `ADMIN`，仅用于开发种子数据，生产不能沿用该行为。

目标规则：所有人都从同一个 IDS 登录页进入；服务端根据 IDS 返回的学号与后台配置决定管理员身份；管理员登录后左侧额外出现管理员 Tab，普通账号完全不显示独立管理员入口，也不能仅靠前端绕过权限。

### P1：中英文和主题支持不完整

- 当前页面文案主要是中文，没有统一的 Web locale/context 或翻译目录。
- `ThemeContext` 目前只有 `system/light/dark` 三态循环。
- `src/app/layout.tsx` 把 `<html>` 固定写成 `className="dark"`，会覆盖或干扰浅色模式初始状态。
- 原始设计要求登录后仍可切换语言，并保留配色主题；旧项目设计说明要求系统/浅色/深色与多套配色主题。新 Web 尚未完成统一迁移。

### P1：校园正式接口未验收

- 校园日程接口目前可返回 `sourceStatus: not_connected` 的空数据。
- 地图接口目前没有正式地图数据源。
- eHall 目前只有官方外链，没有登录交换、课表、成绩、考试、空教室等正式接口。
- 校园网和宿舍水机有适配代码，但需要真实账号和学校上游联调。

### P1：AI/RAG 尚未达到生产可用

### P1：生产部署尚未闭环

- 尚无最终确认的生产 Git 发布流程、systemd/PM2 守护配置、HTTPS 反向代理、备份和回滚入口。
- 生产还需要正式数据库、`AUTH_URL`、`AUTH_SECRET`、IDS 回调 Origin、S3 凭据、AI/RAG 服务和模型配置。
- 当前本地 PGlite、开发密钥和本地种子数据不能用于生产。
- Next.js 14.2.5 的版本提示目前是依赖升级事项，不是上述登录错误的根因。
